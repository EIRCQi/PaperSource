# 文栖 PaperDesk 0.6.0

中文本地文献管理器。无需登录、运行时无需联网服务。需要 Node.js 22.13 或更高版本（推荐 Node.js 24）；首次安装或升级需要联网运行 `npm ci` 安装 PDF 解析依赖；数据仅保存在运行程序的电脑。支持 macOS、Windows、Linux，使用系统浏览器界面。

## 0.6.0 更新：自动读取题录

- **新导入 PDF 自动识别**：读取内嵌题录（Info / XMP）与前两页可提取文字，填入标题、作者、论文关键词、DOI。存在明确发表信息时补充年份，XMP 提供时补充期刊名；不会把文件创建时间当作发表时间。
- **已有文献重新识别**：选中文献，点击详情顶部“识别题录”。逐项显示候选值、当前内容和来源。空字段默认勾选；标题仍等于文件名时也默认勾选，其他已有内容默认保留。勾选需要的字段，点击“填入勾选字段”，核对后再点“保存修改”。取消不改变编辑内容。
- **关键词独立保存**：论文关键词与自定义标签分开；关键词参与搜索、自动分类和 BibTeX 导出，并随草稿、完整备份和恢复保留。已有文献补全关键词并保存后，可以在“自动分类”预览新分类建议。
- **识别失败仍保留 PDF**：密码保护、无可提取文字、损坏文件、缺少依赖或超时都会给出提示。导入汇总显示识别数量；原有导入去重、版本冲突保护继续生效。

识别完全在本机进行，不上传 PDF 或题录，不调用在线 AI / DOI 服务。内嵌元数据可能不准确；首页标题及作者使用排版规则判断，均需核对，不保证每篇都能识别。只提取已有关键词栏，不会为无关键词文献凭空生成关键词。扫描件暂不支持 OCR；复杂双栏、公式标题、字体编码异常可能需要手工修正。旧文献不会在升级时自动改写，请使用“识别题录”处理。

解析器使用 Mozilla [PDF.js](https://github.com/mozilla/pdf.js)；独立工作线程限制每篇识别 15 秒、最多两篇同时识别。资源繁忙时先保留文件，稍后可在详情重试。安装时需保留 npm 默认的可选依赖（包含各平台的预编译组件）。如提示识别依赖不可用，请在项目目录重新运行 `npm ci` 后重启。

## 0.5.0 更新

### 清除文献

进入“回收站”，可选择“彻底删除所选”或“清空整个回收站”。页面会显示数量和部分标题，需要输入对应的 `永久删除 N 篇` 才能执行。清空整个回收站包括当前搜索结果之外的回收站文献，每次最多 10000 篇；选择删除沿用列表每次最多 500 篇的限制。

彻底清除会删除文献库中的 PDF 副本、题录和笔记，不能从回收站恢复；原始导入文件和已经生成的完整备份保留。正常“移入回收站”仍然可以恢复。清除期间会检查文献版本，如果有文献已被恢复或修改，整批停止。正在完整备份时暂不允许清除。

清除使用暂存日志：书目保存失败会把移走的 PDF 放回；异常退出后，下次启动会根据已保存的书目恢复或完成清理。若曾被强制结束，可能仍需按“异常处理”说明处理运行锁。彻底清除不是磁盘安全擦除，旧完整备份中仍可能含有这些文献。

### 自动筛选

左侧新增三个会随题录和标签变化而更新的入口：

- **未分类**：没有任何标签的有效文献。
- **资料待补全**：作者为空，或年份不是四位数字的有效文献。
- **有分类建议**：按当前规则匹配到尚未添加标签的文献。

这些筛选不会移动、删除或改写文献，可以继续叠加搜索关键词。

### 自动分类

点击顶部“自动分类”。系统按标题、文件名、期刊和已保存的论文关键词匹配，支持中英文；分类本身不分析 PDF 全文或调用在线 AI。可给同一文献添加多个分类，并保留已有手动标签。

规则每行一个分类，例如：

```text
定位研究 = UWB, localization, 室内定位
雷达感知 = radar, 雷达, activity recognition
综述 = survey, systematic review, 综述
```

点击“预览分类建议”，核对标题、建议标签和命中关键词；取消不合适的建议后，点击“应用勾选建议并保存规则”。每次最多展示和处理 500 篇，应用后可再次预览处理其余文献。修改规则后必须重新预览。可以选择“仅保存规则”，不修改已有文献。

“导入时自动添加匹配标签”默认开启，作用于后续新增 PDF，可以取消勾选并保存来关闭。重复文件不会被重新分类；已有文献通过预览确认后分类。分类设置随完整备份保存。最多 40 个分类，每个分类 1 至 30 个关键词；单篇最多 50 个标签。

## 0.4.0 更新

- 新增列表多选与本页全选，可跨页选择，每批最多 500 篇。
- 批量设置阅读状态、星标，追加或移除一个标签，以及移入回收站和恢复。
- 批量操作先检查全部文献版本，任何一篇冲突或校验不通过，整批不修改；不会出现部分成功、部分失败的结果。
- 新增“刷新列表”和“查看本次新增文献”，导入完成后可以直接整理新文献。
- 刷新、切换分类、标签或搜索关键词会清空批量选择，避免误操作筛选范围外的文献；翻页与排序保留选择。
- 修复导入后的列表刷新可能盖过较新编辑结果的问题，以及保存后多选控件的启用状态。

### 批量整理怎么用

1. 勾选文献左侧复选框，或点击“本页全选”（只选择当前页的最多 50 篇）。翻页可继续选择，总选择数始终显示在列表上方。
2. 点击“批量整理”，在弹窗中核对数量与文献标题摘要，然后选择操作。添加标签会保留原有标签并去重；每次只添加或移除一个标签。
3. 点击“应用到所选文献”。如有未保存的当前编辑，先保存再批量整理；导入过程中请等待导入完成。
4. 冲突时本次整批不修改。关闭弹窗，点击“刷新列表”，重新选择文献后再执行。
5. 回收站的“批量整理”提供恢复；列表上方另有“彻底删除所选”和“清空整个回收站”。移入回收站本身不会删除 PDF。

“查看本次新增文献”只包含最近一次导入中新添加的文献，不包括重复文件；刷新整个浏览器页面后不保留此临时分组。

### 从 0.1.0–0.5.0 升级

先停止旧程序并备份整个 `PaperDeskData`。确认 `node -v` 至少为 22.13（推荐 24）。在克隆的项目目录执行下面的命令，刷新已有浏览器页面；旧文献库兼容，无需迁移。

```bash
git pull --ff-only origin main
npm ci
npm run open
```

如果此前通过 ZIP 下载，请从 GitHub 下载新源码，解压到新的程序目录，然后运行 `npm ci` 和 `npm run open`；不要在没有 `.git` 的目录执行 `git pull`。数据仍在原 `PaperDeskData` 目录。

如果出现版本冲突，先复制想保留的编辑内容，点击“重新载入”，然后在最新版本中合并并保存。重新载入会在确认后放弃本页未保存的修改。旧页面没有版本信息时会拒绝保存，刷新即可使用新版。

## Mac 启动

解压软件包。打开终端输入 `cd `（注意空格），把解压后的项目文件夹（例如 `PaperSource-main`）拖进终端，按回车，然后运行：

```bash
npm ci
npm run open
```

首次 `npm ci` 完成后，日常也可以双击 `Start.command`。如果系统不允许双击运行，请使用上面的终端启动方式。Windows 可双击 `Start.bat`；Linux 使用 `npm run open`。

启动后浏览器自动打开。默认地址 http://127.0.0.1:4321，端口被占用时自动选择空闲端口，以终端打印地址为准。使用时保留终端窗口，按 Control+C 退出。关闭浏览器标签页不会停止程序。

## 使用

1. 选择“导入 PDF”，支持多选；“导入文件夹”递归导入选中文件夹里的 PDF。拖放支持 PDF 文件，不支持直接拖放文件夹。
2. 单个文件最大 50 MB，逐个上传，不会移动或改写原文件。内容完全相同的 PDF 只保留一份。
3. 选择文献，核对或填写标题、作者、年份、期刊、DOI 和论文关键词，用中文或英文逗号分隔标签。
4. 设置待阅读、阅读中或已读完，勾选星标，记录笔记，然后点击“保存修改”。未保存内容在切换文献或关闭窗口时会提示。
5. 打开 PDF 新标签页阅读，或展开内嵌预览。显示能力取决于浏览器内置 PDF 阅读器。
6. 搜索覆盖标题、作者、年份、DOI、期刊、论文关键词、标签、笔记。搜索不包含 PDF 正文。回收站中的文献仅在回收站搜索中显示。
7. 移入回收站后可恢复；需要释放文献库副本占用的空间时，进入回收站确认彻底清除。重复导入回收站内的文献时，请先恢复。

## 数据与备份

默认目录：用户主目录下 `PaperDeskData`，Mac 通常是 `/Users/你的用户名/PaperDeskData`。界面“使用与备份说明”展示实际位置。

- `catalog.json`：全部题录、笔记和分类；原子替换写入。
- `catalog.json.bak`：上一次成功修改前的题录快照，并不是完整历史备份。
- `files/`：按内容哈希命名的 PDF 副本。
- `running.lock`：防止多个程序同时写入同一文献库的运行锁，正常退出自动删除。

**完整备份**：先 Control+C 退出程序，再复制整个 `PaperDeskData` 文件夹到备份磁盘。**恢复**：先关闭程序，用备份替换该目录，再重新启动。可以先将现有目录改名保留，避免覆盖后无法撤回。

### 一键完整备份

点击顶部“完整备份”。程序把**点击时已保存的内容**复制到数据目录下的 `backups/backup-...` 文件夹，备份完成后界面显示具体路径、文献数量和 PDF 总大小。备份期间仍可编辑；稍后的修改属于下一份备份。

备份包含 `catalog.json`、`files/` 和带校验信息的 `manifest.json`。文件缺失或损坏时，备份失败并清理未完成副本；原库不变。备份需要接近当前 PDF 总大小的可用磁盘空间。备份与原库位于同一磁盘，**请将完成的备份文件夹复制到外部磁盘**。备份不会复制历史备份文件夹，也不会自动删除旧备份。

### 从完整备份恢复

在项目目录中运行，路径请替换为自己的实际路径：

```bash
npm run restore -- "/备份位置/backup-..." "/Users/你的用户名/PaperDeskRestored"
```

新文献库目录必须不存在，其父目录必须已存在；省略第二个参数时，程序在用户主目录自动创建一个新的 `PaperDeskRestored-...` 目录。题录和 PDF 的校验全部通过才算恢复成功。源备份和原文献库都不会被覆盖。

在 macOS / Linux 上，用恢复后的目录启动：

```bash
PAPERDESK_DATA="/Users/你的用户名/PaperDeskRestored" npm run open
```

Windows PowerShell 中：

```powershell
$env:PAPERDESK_DATA="C:\Users\你的用户名\PaperDeskRestored"
npm run open
```

每次启动恢复库都要指定此目录。确认恢复内容正常后，也可停止全部文栖进程，保留原库副本，再手动将恢复目录移到默认 `PaperDeskData` 位置。

### 书目导出

“导出书目”提供两个选项，均导出已保存内容，且不受当前搜索或标签筛选限制：

- JSON：全部题录及笔记，含回收站记录，不含 PDF。本版不提供书目 JSON 导入；它不是完整备份格式。
- BibTeX：全部有效文献，不含回收站或笔记；文献详情也可导出单篇。作者使用中文或英文分号分隔后，会转为 BibTeX 的作者列表。尚无文献类型字段，因此条目统一用 `@misc`，需要时在引用软件里补充类型。

BibTeX 文件使用 UTF-8，保留中文。LaTeX 工程处理中文的能力取决于所用工具链；程序将输入按普通文本转义，不将元数据解释为 LaTeX 命令。格式参考：[BibTeX 格式](https://www.bibtex.org/Format/)与[特殊字符](https://www.bibtex.org/SpecialSymbols/)。

可用环境变量 `PAPERDESK_DATA` 指定其他数据目录（不要同时让多个设备写入同步盘目录），用 `PORT` 指定首选端口。

## 异常处理

- 提示“数据目录已锁定”：先检查另一终端中是否已经运行文栖。若曾强制关机或强制结束进程，确认所有文栖进程均已停止后，再删除数据目录内的 `running.lock`。
- 数据库损坏时程序停止并报告错误，不会自动覆盖。关闭程序并备份整个目录后，可检查 `catalog.json.bak` 或从完整备份恢复。
- 提示保存失败：保留页面中的笔记，检查磁盘剩余空间及数据目录写入权限，再重试保存。
- 浏览器打不开 PDF：使用“打开 PDF”，检查浏览器 PDF 阅读设置。

## 范围

这是可运行的首版本地应用，尚非签名安装包。未实现 PDF 全文搜索、OCR、DOI 联网检索、BibTeX 导入、RIS、云同步或 PDF 标注。自动题录识别失败时，标题回退到文件名，其他题录手工补充。适合个人中小规模文献库，超大规模性能尚未验证。

服务仅绑定本机 127.0.0.1，校验 Host、Origin 和会话令牌。不包含遥测或远程 API。界面不提供账号系统，不用于共享电脑上的用户隔离。PDF 自动识别使用锁定版本的 `pdfjs-dist`，其余服务使用 Node.js 内置模块。
